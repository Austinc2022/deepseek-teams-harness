name: learned-mechanical-write-time-evidence-84e4
description: When asked to fix a claim-drift / evidence-discipline defect (counts, fact ids, approvals contradicted by re-check; status re-hash instead of artifact) where prose rules already exist in the agent's role and are being violated anyway.
---

1. Classify the failure as discipline, not capability: reviewer re-checks contradict published claims, and the role already carries the rule in prose. Do NOT propose more role prose — a 6-rule EVIDENCE DISCIPLINE block measurably failed (25/100 for 12+ hours), and role-text edits auto-score and can roll back (fact fd85e74f140: 0.81→0.6 rolled-back). Prefer a skill/playbook plus a harness-level mechanical gate.
2. Design the claim row first: every claim in the report is a row `claim — exact command/glob/knowledge_get — verbatim output excerpt — strength`. Counts carry the literal Glob/Grep pattern; fact ids carry "knowledge_get ran this cycle, status+strength copied"; approvals carry the verbatim reply text plus source path, or the word "unverified".
3. Write-time protocol: the evidence battery runs AFTER the final content edit and immediately before filing. (a) re-run each count's exact command; (b) resolve every hex id with knowledge_get in the same turn as writing; (c) copy every approval quote from the source file, not from memory; (d) existence-check every deliverable path the report names. Evidence older than the last edit does not count.
4. Enforce mechanically at harness level, outside the agent's tool grant: a deterministic linter invoked by a Stop hook (block the turn end) or a PreToolUse deny on report writes, scanning the draft for bare numbers, hex-looking ids, "measured", "approved" — each hit must carry its stamp. Two-sided-test the gate itself: an unstamped count must fail it, a fully stamped report must pass.
5. Independent verification must re-run tools or use a fresh context. Chain-of-Verification (arXiv 2309.11495) shows a model that re-reads its own draft repeats its own hallucinations; self-check by introspection is not verification.
6. Deliverable-first: the report may only reference artifacts that already exist on disk; a status write-up is never the deliverable.
7. Failures to expect: stale counts taken before the last edit; paraphrased/elided quotes ("red: none" style, fact f286904121c); line numbers instead of content (they drift same-day); phantom well-formed ids copied from other agents' text; Stop-hook infinite loops (bound the attempts); the checker script itself untested.
8. When recommending a GitHub SKILL.md, fetch the raw file and the repo tree before naming it — skills can live in unexpected paths (illus-consulting/apd-gauntlet keeps them under .claude/skills/, and its root has no skills/ directory).
