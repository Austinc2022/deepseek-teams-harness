# Auditing a multi-region Meta Quest store package

Work region by region and language by language; the same product must not promise different things in different regions.

## Steps

1. **Inventory.** For each region × language check all nine parts exist: listing copy, trailer brief, key art brief, price tier draft + rationale, age rating questionnaire draft, data/privacy questionnaire draft, compliance checklist, launch plan, owner submission checklist. Missing part = blocking finding.
2. **Cross-region consistency.** Same feature claims and comfort claims everywhere; localized copy must not add or soften claims; price tiers must follow the stated rationale across regions; flag machine-mistranslated or contradictory copy.
3. **Listing copy audit.** Every claim must be backed by something actually in the build (no vaporware). Check store-policy limits: no superlatives ("best", "#1"), no competitor comparisons, age-appropriate tone, no promises of features not shipped. Use the ASO lens for keyword/first-line strength, but policy violations outrank polish.
4. **Price tier rationale.** Each tier must cite evidence — comparables, regional norms, willingness-to-pay — not vibes. Verify cited comparables exist (websearch); check tax/VAT display norms for the region.
5. **Age rating and privacy questionnaires.** Answers must match the actual build: data collected, online/social features, user-generated content, motion/comfort profile. A rating answer the build contradicts is blocking.
6. **Compliance checklists.** Each entry must name a concrete obligation and its owner (e.g. GDPR lawful basis, retention period, age gate, EU DSA trader information). "GDPR compliant" with no obligation listed = finding. Verify region-specific rules you flag with websearch and cite the source; never assert a regulation from memory.
7. **Launch plan.** Named target segment consistent with the rest of the package; channels, timing, wishlist/pre-order steps, and at least one measurable goal. Vague "build awareness" goals = minor finding.
8. **Submission checklist.** Each step owner-actionable in the Meta developer dashboard (named screen/field), ordered, with asset specs, rating certificate and privacy policy URL prerequisites called out.

## Before handover — verify
- [ ] A per-region × language matrix shows part-by-part completeness.
- [ ] Every finding is ranked blocking / major / minor with an exact quote.
- [ ] Every regional rule or rating-board fact you assert has a websearch source.
- [ ] Consistency findings name both regions that disagree.

## Mistakes to avoid
- Auditing only the default language and assuming the rest.
- Treating polished copy as compliant copy.
- Asserting regional regulations without a checked source.
