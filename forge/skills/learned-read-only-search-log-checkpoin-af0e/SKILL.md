name: learned-read-only-search-log-checkpoin-af0e
description: When a design/research run accumulates external evidence (search queries with URLs, fetched store pages) and you cannot write files (read-only analyst, no Write tool): the run can die at any turn and the log must survive.
---

1. Accept the constraint: with no Write tool, your only durable media are plan_items notes, the report body (report_to_coo summary/evidence), and the knowledge store. Disk files are NOT available to you — never plan to write them.
2. Checkpoint as you go, not at the end: after each search batch (4-6 queries), fold the query string + kept URLs into a plan_items note or a running report draft immediately. A plan note that says "24 searches done" without the rows is not evidence — the rows are the evidence.
3. The final report must carry the log verbatim: one row per query — date, engine/store, exact query string, kept URLs. The know-how rule stands: no search log = no evidence; a claim whose rows are missing is dropped, not listed.
4. If an earlier turn's log is lost (context death, no artifact), do NOT cite it: say the log was lost, show the Glob/Grep that proves the artifact is missing, and re-run the decisive queries under today's date. Re-run beats reconstructed — reconstructed timestamps prove nothing.
5. Verdicts ride on fetched pages, not snippets: fetch the 2-4 decisive store/official pages and quote the verb line from the page text in the report's evidence rows (strength: measured). Snippet-only verdicts are labelled argued.
6. Salvage order when context is gone: plan_items notes (survive) > transcript_search/knowledge_search of your own run id > state.json ticket briefs (grep with short -o windows, long lines are omitted). Rebuild the structural templates from there before redoing creative work.
