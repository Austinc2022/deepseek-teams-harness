description: When scouting methods for a multi-item kit/game ticket whose session died at 'Reached maximum number of turns (N)' (turn exhaustion, not the 32k output cap) and some items remain on disk.
---

1. Classify the death: output cap ('exceeded the NNNN output token maximum' = oversized response) vs max-turns ('Reached maximum number of turns (N)' = message count exhausted; per Claude Code docs the run 'exits with an error instead', so NO summary was produced and only on-disk checkpoints survive) vs wall-clock limit. The mitigation differs: cap deaths need smaller writes; max-turns deaths need fewer, batched messages and a report that already exists on disk.
2. Read the ticket folder's NOTES.md and quote the live cursor (last 'Next:' line) and which rows carry red+green quotes; read ONLY the spec lines that enumerate the remaining items. Classify each remaining item: required row, allowed disposition ('NOT LANDED with the measured reason'), or cut ('cut by the COO'). Count units.
3. Turn arithmetic: measure the dead session's cadence from checkpoint timestamps (messages burned per landed item). Budget <=5 messages per remaining unit = (a) one message of ONLY batched parallel reads (spec offset/limit + Grep), (b) one Edit <=120 lines, (c) ONE chained Bash doing plant/swap -> test -> log red -> restore (cmp clean) -> test -> log green, screen shows tail -25 only, (d) one message with two parallel Edits: NOTES row + CHANGES row ending 'Next: <action>'. Reserve >=25 messages: FINISH battery ~18, report-time swap-red refresh ~10 (one batched script), report assembly ~6.
4. Recommend skipping per-item full-suite runs (run the item's own test file only; the suite runs once at FINISH) — this was the biggest avoidable burn in observed deaths.
5. If budget is tight, prefer dispositions for optional rows and land the required code rows (K-group) first; the survival floor is one durable checkpointed artifact within the first ~10 messages (f1027748939).
6. Evidence: every red must be verbatim from a run in THIS ticket folder and re-measured at report time (mutation style: fix swapped out, the named test must die); re-open every cited file:line and number in the report turn; check which mode's branch actually FAILs on the shipped tree before quoting a row-level red (kit mode often REPORTs where game mode FAILs).
7. FINISH = one atomic battery after the LAST src edit (test -> smoke -> freeze/gate-lite -> fork proof with planted FAILs -> copy logs -> destructive hygiene LAST, nothing after). Then assemble the <=60-line report FROM the NOTES/CHANGES ledger lines; never re-derive a grand essay at the end (n=3 report-time 32k deaths).
8. What goes wrong: opening with whole-tree reads then a plan (observed: 25 reads, 0 edits, death); 'red: none' or paraphrased quotes (fails claim verification); file:line drift after later edits; runs after hygiene re-dirty scratch; assuming the session will end with a turn to write the report — write the report draft to disk before the last items instead.
