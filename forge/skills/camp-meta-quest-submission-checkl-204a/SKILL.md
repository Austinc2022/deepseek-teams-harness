Use when producing the step-by-step owner submission checklist for the Meta developer dashboard (store-package/submission-checklist.md).

1. Verify the current submission flow and field names via websearch (Meta developer documentation and dashboard docs) — the UI changes. Note the date checked in the checklist header.
2. Build the checklist in this order, one entry per action, each with: what to prepare (input artifact from store-package/), where it goes in the dashboard, and what blocks review if wrong:
   a. Prerequisites: developer organisation verification, account roles, app ID, target regions/availability.
   b. Build: upload/channel steps (release channel, versioning, staged rollout option).
   c. Store listing: copy fields per language, asset uploads (cross-reference creative briefs and their specs), trailer upload.
   d. Pricing & availability: per-region price tier entry from the price-tier draft, currency/tax notes.
   e. Ratings: upload/complete the IARC rating (cross-reference the ratings questionnaire draft).
   f. Privacy: privacy policy URL and data disclosure form (cross-reference those drafts).
   g. Submit & review: submission order, expected review loops, launch date scheduling per region.
3. Each step names an owner. The agent drafts; the owner performs the dashboard actions — the checklist states this explicitly and never claims a submission was made.

Verify before handover:
- [ ] Every checklist step cross-references a real file in store-package/ or is marked as owner-only input.
- [ ] Every region/language in the package appears in the listing and pricing steps.
- [ ] Field names and flow match the docs checked (with date), not memory.
- [ ] Steps that block review (ratings, privacy form, build) are flagged as blockers.
- [ ] No step claims an action was completed that only the owner can perform.
