---
name: camp-tc-character-prop-artist-pro-601a
description: Building a distance-preview sheet for flat/HTML/WebXR props that must show solid silhouettes at labelled viewing distances and judge whether a small-detail legibility requirement (engraved text, tiny markings) can physically pass.
---

1. Draw each asset's SVG in centimetres at 500 px per metre so the asset page shows 1 m size at 1 m. Give each asset a `?silhouette=1` mode that forces every fill to black, hides UI chrome, and makes the stage `position:absolute; inset:0` so an iframe of any pixel size scales the drawing.
2. Preview sheet embeds iframes `src="asset.html?silhouette=1"` with literal width/height attributes: `px = S_metres / distance_m * 500`. Sizes: 1 m = S*500, 2 m = S*250, 3 m = S*166.7. Label every figure with distance and px. Round to integers, keep the asset's aspect ratio.
3. Verdict rule for silhouette props: whole-object angular size at 3 m = S/3 rad; bold chunky props of 0.25-0.5 m subtend 5-8 deg and PASS. Never judge by pixels alone; write the degrees in the verdict line.
4. Legibility trap check (engraved/tiny text): compute angular size of the TEXT, not the object. cap_height_mm / 3000 mm gives radians; multiply by 3438 for arcmin. Legible glyphs need ~5-10 arcmin cap height even for ideal black-on-white (1 arcmin/acuity stroke; glyphs carry several strokes); engraving is shadow-read, ~10-20% contrast, so the threshold is higher. Signage cross-check: cap height >= distance/200 (15 mm at 3 m). Headset cross-check: ~25 px/deg * deg cap height — under ~2 px means unrenderable.
5. If the requirement fails: mark FAIL explicitly, show the arithmetic on the sheet (whole-object angle, per-glyph angle, required angle), never fake a pass or silently drop the item. Offer ONE concrete buildable substitute that does NOT pretend to preserve the failed detail (e.g. larger shape-coded tag), and state what is lost (street name becomes a shape code). If it needs a spec change (e.g. 170 mm plate for 15 mm letters), say so plainly.
6. Verify before finishing: (a) node script checking px = S/d*500 for every embedded size (derive S from the 1 m figure, check 2 m/3 m within 1 px); (b) tag-balance scan with open-tag regex `/<tag(?=[\s>])/` — beware over-escaping `\\s` inside shell-quoted node -e, prefer a .mjs file; (c) greps for idle/action named states, trigger button, silhouette mode, PASS/FAIL verdict counts. SVG animation pivots: CSS `transform-origin` on SVG elements is in viewBox USER UNITS (cm here), not CSS px of the page.
7. Keep the checker script reusable (accept props-dir + sheet name as arguments) in the agent home files/ directory.
