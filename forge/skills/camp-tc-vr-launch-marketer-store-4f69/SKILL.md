# Reconciling source listing vs approved build facts before drafting store copy

1. **Split the inputs.** Treat the source listing as *style and structure* and the approved build facts as *the only factual ground truth*. Every sentence you write must be traceable to one of them; a claim that appears in neither is banned (platforms, fps, awards, reviews, prices, translations).
2. **Diff claims, not words.** List every factual claim in the source (durations, features, input methods, languages, performance). Mark each: confirmed / contradicted / qualified-but-omitted by the build facts.
3. **Correct contradictions openly.** The build facts win. Rewrite the claim (e.g. "15 minutes" → "rund 12 Minuten" when build facts say 12 median) AND list the correction + reason in the notes. Never silently fix and never keep the wrong number.
4. **Close misleading gaps.** If the source implies something the build facts deny (e.g. "subtitles" when there is no voice acting), re-render the feature in plain terms and state the negative fact ("keine Sprachausgabe") — this is a correction, not a new claim.
5. **Attach every caveat to its feature.** Experimental / partially supported features must carry their qualifier inline ("experimentell, möglicherweise nicht auf allen Headsets"), never in fine print only.
6. **Translate nothing that is a name or a tech term.** Product titles stay as shipped unless the owner approves a localised subtitle; keep terms like WebXR.
7. **Measure the target language.** German expands 10–35% over English: count characters in the *target* text, never the source. (Tool: count_listing_fields.)
8. **Notes section is mandatory and structured:** (a) claims changed or dropped and why; (b) ambiguities left open because the source is unclear; (c) items needing a native reviewer (register, word choice, punctuation); (d) items needing legal/compliance (duration claims, capability claims, platform implication, IP in titles).
9. **Mark the deliverable DRAFT — owner review**, and say explicitly that nothing was submitted or published.

Common mistakes: trusting the listing's numbers over build facts; writing "Untertitel" when there is no speech; naming a platform (Quest) in a limitation, which implies support; adding a desktop fps figure to copy that will be read on standalone hardware; assuming store field limits from another store/locale.
