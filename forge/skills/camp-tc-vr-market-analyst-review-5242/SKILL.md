name: camp-tc-vr-market-analyst-review-5242
description: When a review sample must decide which complaints justify a feature, especially when a feature list was already picked from best sellers.
---

1. Read every review in the sample; assign each exactly one primary theme — the dominant problem or the explicit "please add X" request. Write the rule down before counting.
2. For mixed reviews (e.g. "short for the price", "short and easy"), pick one by a stated tie-break (content quantity before price; content before difficulty) and flag the judgment calls in a caveat.
3. Count positive reviews that request more content as that content theme only if the request is explicit; otherwise mark them positive/no-gap.
4. Compute share = count / total reviews. Treat themes with fewer than 5 reviews as not evidence for a feature, regardless of how vivid the quote is.
5. Separate "most frequent complaint" from "gap worth building": frequency does not imply buildability or impact. Ask whether the theme is a content/production or pricing decision versus a missing mechanism that blocks the core loop. Only themes passing the 5-review threshold plus that buildability test get funded.
6. Never infer sales location from reviewer store region; report the region distribution with the explicit limit that it is reviewer metadata, not units. Do not turn rating counts into revenue without a sourced conversion rate — label such numbers as estimates or omit them.
7. If source files lack URLs, say so and state that external verification failed; cite file + line and capture date instead of inventing a URL.
8. For extra evidence, propose public pages, archives and anonymous first-party funnel telemetry only — no outreach, purchases or publishing.
