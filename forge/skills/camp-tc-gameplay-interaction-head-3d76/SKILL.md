name: camp-tc-gameplay-interaction-head-3d76
description: Verifying a WebXR/three.js interaction module (grab/hover/locomotion/comfort features) without a headset or browser available.
---

1. Split the work into a pure three.js scene builder (no DOM) and an interaction module that takes {scene, camera, renderer, canisters/rig} and exposes {state, update, dispose} plus grab/release hooks. The scene builder is shared by the HTML page and the test, so both exercise the same world.
2. Build a Node smoke test with stubbed DOM (fake element with style/children/appendChild/remove/getBoundingClientRect), a fake renderer ({domElement: canvas-listener stub, xr: undefined or a fake {isPresenting, getController}}), and real three.js. Use `globalThis.document/window/navigator` assignment before importing the module.
3. Exercise desktop input by firing canvas/window listener maps directly: project each target object's world position to screen coords ((x+1)/2*w, (1-y)/2*h) for mousemove raycasts, then fire click/keydown. Assert on scene-graph facts (parent changes, world-position distance to camera, exact restored transforms), not just state flags.
4. Exercise the XR path by giving the fake renderer an `xr` with `isPresenting: true` and `getController: () => new THREE.Group()`. Expose the created controllers from the module so the test can `dispatchEvent({type:'selectstart'/'squeezestart'/'squeezeend'})` on real THREE.EventDispatcher objects, and set `controller.userData.inputSource = {gamepad: {axes: [...]}}` to drive thumbstick logic. Position controllers in world space to aim the ray at a known object.
5. Regression-assert the classic defects: held object must keep a stored offset (never copy camera.position into it); snap turn must land exactly on the quantized step and stay on the grid; comfort vignette must exist BOTH as DOM overlay and as a camera-attached scene mesh (CSS is invisible in XR); desktop input must reach the 3D objects, not just a status div.
6. Verification ladder: node --check on every .js/.mjs (works with "type":"module"), run the smoke test, extract inline <script type="module"> from the HTML with a small node script and node --check it, curl every module URL the page loads for 200s.
7. Headless browsers will likely fail in a sandboxed session: Chrome's ProcessSingleton needs an AF_UNIX bind, which macOS Seatbelt denies (EPERM). Detect with a one-liner node net.createServer().listen(tmpdirPath) test. Report the browser check as an honest FAIL/blocked with the exact error and the manual command, rather than claiming a clean page load.
8. For any comfort claim, keep software verification strictly separate from human comfort: PASS rows prove the code behaves; comfort itself needs a user study (SSQ, session length, target hardware). Never let a passing smoke test or a viral clip support "comfort validated".
