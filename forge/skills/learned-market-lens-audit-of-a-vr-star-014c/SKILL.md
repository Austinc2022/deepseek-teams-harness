description: Critiquing a starter kit / template / tooling ticket through the market lens (hook, buyers, comparables, store-page honesty, $10M path) rather than a game.
---

1. Identify the kit's store-page output machinery: key-art capture (hero shot), screenshot framing guards, the commercial block (hook / buyer / comparables / price / $10M path), and the evidence-quote system that keeps public claims tied to measured runs.
2. For every guarantee a doc claims ("FAILs the smoke", "the README shows"), verify at the LAYER the claim names: a unit-test red does not prove a smoke-level FAIL. Read the pass condition itself (e.g. smoke status assembly line) and grep for the flag the claim mentions; a field that is written but never read in the pass line = false guarantee.
3. Anchor the money column against the company's own revenue tool (target gross vs net after store cut). Compute both back-solves at the planning price; if the template back-solves only the flattering one, that is a must-fix (the verdict line must name its target).
4. Check provenance consistency across artifacts: template labels ("no public source found") vs the calculator/tool assumption strings (named agencies). Run one public search to see if the named source exists; 0 hits + a named source = citation hazard for store pages.
5. List what a store page can honestly claim from the shipped evidence (measured: render stats, materials, audio counters, framing numbers) vs what it cannot (fun/comfort/headset feel: n=0 playtests, no headset run) — the kit should force the second list into Open risks.
6. Treat screenshots as store assets: subject-out-of-frame, camera-inside-geometry and non-core-verb key art are the three store-killers; check which have automated FAILs and which rely on human self-check rows.
7. Weigh the score on the honesty and completeness of the market machinery, not the effort log. Name file:line for each defect and the concrete fix.
