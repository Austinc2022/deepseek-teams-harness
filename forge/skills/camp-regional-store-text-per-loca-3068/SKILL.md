# Regional store text per locale

When: producing regional store text for the app/game's store listings.

1. **Work per store per locale.** Quest/Meta, Steam, App Lab, and Google/Apple each define their own fields and character limits (title, subtitle/short description, long description, keyword fields, developer name). Never reuse one template across stores or across locales.
2. **Start from the ASO-optimised English master** (the listing produced with aso / product-marketing). Extract every field, note its per-store character limit, and keep the game name consistent everywhere (add a localised subtitle in CJK markets rather than transliterating the title unless local practice demands it).
3. **Transcreate, do not translate.** Localise the value proposition and calls to action; adapt cultural references, punctuation (full-width in CJK), units, age-rating wording; keep idioms out. If the target language expands (German, French), the field limit is hit after translation — re-count, never trust English counts.
4. **Keyword fields per locale.** Research with websearch what players actually type in that language — many markets search English terms even for localised listings. Avoid words already present in the title where the store de-duplicates; respect each store's separator convention.
5. **Regional differences.** Note price/monetisation mentions, seasonal hooks and review-culture cues per region; flag anything that would read as machine translation to a native reviewer.

**Verify before handover:** character counts measured in the target language and within each store's field limits; title and developer name consistent across all locales and stores; every field translated or explicitly left English with a reason; keyword lists differ per locale where search behaviour differs; all counts and choices recorded in localisation.md.
