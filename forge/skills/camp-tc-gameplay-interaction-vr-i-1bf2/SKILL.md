description: Verifying WebXR/desktop interaction behaviour and "no console errors" without a headset, for a scene served over a local HTTP server.
---

1. Put testable logic in a dependency-free module (plain {x,y,z} vector math) so a Node bench can drive it headlessly; let the browser scene wrap it. 2. Bench rows assert STATE (yaw degrees, object identity, strength values), never event/click counts; give each row a numeric detail string. Run the bench against BOTH the new module and the old/inherited file (accept a module path argument) to prove which rows the old one fails and that keeper rows still pass. 3. Serve with `python3 -m http.server <port> --bind 127.0.0.1` in the background; expose a `window.__debug` hook with the objects, camera and input helpers the check needs. 4. Verify the page with CDP: spawn the playwright headless shell (ms-playwright cache; NOT Google Chrome.app which needs more permissions), user-data-dir under $TMPDIR via path.join (TMPDIR has NO trailing slash — naive concat creates an unwritable path and Chrome exits silently; capture chrome stderr while debugging), poll /json/list for the page WS. Collect Runtime.consoleAPICalled error/warning + Runtime.exceptionThrown + Log.entryAdded error; also treat CDP command error payloads as failures. 5. Input.dispatchMouseEvent: button must be the string 'left' (a numeric 0 silently fails) and 'mouseMoved' must omit button/clickCount; Input.dispatchKeyEvent needs code+key for listeners reading e.code. 6. For hover/grab proof, evaluate in-page: project the object's position with three.js (obj.position.clone().project(camera)) to get dispatch pixels, then read back hovered/grabbed state and HUD text — state, not screenshots. 7. After edits to Node-loaded files, re-run the bench: a stray `npm init -y` package.json sets "type":"commonjs" and breaks ESM .js imports; set "type":"module" explicitly. Common failures: forgetting the page must be served over HTTP (file:// breaks module imports), and asserting click counts instead of state.
