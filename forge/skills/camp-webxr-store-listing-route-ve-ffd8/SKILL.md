When: writing the store-listing section of plan.md — the verified route for listing a WebXR/three.js app on the Meta Quest / Horizon Store.

1. Identify the exact store and current programme names (Meta Horizon Store; note App Lab was merged into it — do not cite stale programme names without checking).
2. Search official Meta developer documentation first (developer meta quest docs, Horizon Store / upload guidelines, VRCs), then reputable secondary sources. Use websearch; record the query used.
3. Determine and cite the concrete route for a browser WebXR app: whether it can ship as-is (web distribution / Quest Browser), or needs a wrapper APK (e.g. 2D/VR shell), or native port. Quote the requirement that decides this.
4. Record listing requirements: developer account and fees, age rating (IARC), data disclosure / privacy policy, review criteria and typical review times, content policies, region availability.
5. Record regional availability and any region-specific listing or pricing constraints.
6. If a claim has no primary source you can quote, write it in the plan as "UNVERIFIED — searched X, Y on <date>" instead of stating it. Never invent policy numbers, fees or timelines.

Checklist before handover: every listing claim has a source URL and access date; primary docs preferred over forum posts; unverified claims visibly flagged; the route is stated as one concrete step sequence (account → build → rating → submit → review).
