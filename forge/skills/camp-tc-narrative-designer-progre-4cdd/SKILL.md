description: Reviewing or writing a progression/retention document for a game concept where retention claims need evidence and falsification.
---

1. Split every claim in the draft into: player-facing design claim, retention hypothesis, or borrowed benchmark. Reject any benchmark percentage carried as a target without local data.
2. For each claim ask: what local evidence supports this? If only survey hypotheticals, small-n demos, or benchmarks from another platform/genre exist, write "no / not enough evidence" and define what to measure instead (instrumentation first: return tracking, per-tempo accuracy, quit timestamps).
3. Cross-check design claims against raw demo data: e.g. if the draft front-loads the hardest move and the telemetry shows early quits at the same timestamp, reject the claim explicitly with the data point and quote.
4. For every retained hypothesis write a measure = observation method + sample + a numeric result that would falsify it. A hypothesis without a falsifier is not shippable.
5. Trailer/marketing asks are not player goals: satisfy them via sandbox/pro exhibition builds or scripted charts, never by degrading onboarding. State this explicitly for the producer.
6. Prefer mastery, social-compare and unfinished-progress return hooks over extrinsic daily payouts when the survey data weakly supports payouts (hypothetical survey yes/no is weak evidence).
