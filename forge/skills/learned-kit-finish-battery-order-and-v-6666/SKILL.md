name: learned-kit-finish-battery-order-and-v-6666
description: When finishing a studio-kit ticket (FINISH battery: suite, real-browser smoke, freeze-check, gate-lite, fork proof, hygiene) or when a freeze verify-copy or fork fails tests that pass in the real tree because file cites resolve only outside the tree.
---

1. FINISH order (evidence first, hygiene LAST): fresh kit-mode smoke (writes evidence + quote blocks) -> fix docs rows -> final `npm test` -> run freeze-check + gate-lite -> fork proof -> hygiene (rm scratch strays like scratch/smoke-out.json, keep base/ only) -> no test or smoke after hygiene (they regenerate scratch). Smoke always leaves scratch/smoke-out.json; delete it before the gate run you quote.
2. Freeze-check runs the whole suite in a nested verify copy (kit/scratch/freeze/verify). A test that resolves files via `root/../logs` passes in the real tree but fails there, because the copy's `../logs` is the freeze log dir. Diagnosis: read kit/logs/test.log (the freeze trap copies the verify run's logs there).
3. Repair without patching the checker: copy the cited files into the tree path the resolver tries FIRST (e.g. kit/logs/<name>) so direct-path resolution works in the real tree, the verify copy AND any fork. Count tree paths against kit.config.json file caps before copying (total cap is tight). Red = the failing freeze run (quote FAIL rows), green = re-run (quote PASS rows).
4. R1 NOTES-claims scans ticket-root NOTES.md: any line naming a *.json with PASS/FAIL/NOT RUN must match evidence on disk NOW. Fix historical quotes by appending '(superseded run, not on disk)' — lines containing 'control', 'red' or 'superseded' are exempt (per-line, so keep risky quotes on a line that carries one of those words).
5. Fork proof: run the README command word for word into a sibling of kit/, quote the K5 node_modules line, run the fork's smoke (game mode) for framing, gate-lite for controls/hero rows, freeze-rows for the R1/R2 planted FAILs (gate-lite lacks the hero self-check row; freeze-rows has all 21). Plant the R1 false NOTES line and remove it in the same shell call so nothing false survives a cut turn. Delete the fork via node fs.rmSync (the rm guard false-positives on workspace subpaths).
6. Keep every quoted log in the ticket-root logs/ folder; verify names with ls before filing. Pipe runs through tail and end with `echo TAIL-DONE` (a tail ending in 'Error: ...' renders as a failed call). zsh: never echo bare === (= expansion).
