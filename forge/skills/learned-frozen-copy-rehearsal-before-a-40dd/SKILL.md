# Frozen-copy rehearsal (read-only reviewer side, plus the builder rows it produces)

Why: a build folder can pass every check while the FROZEN copy fails. The freeze leaves out scratch/, logs/, dist/, node_modules and nested tree copies. Tools, config and docs that point into those folders break silently, and audit-index commands that regenerate evidence change the frozen copy while the auditor is working in it. Neither shows up when the checks run in the build folder.

## Steps (read-only, about 10 tool calls)
1. **List what the freeze excludes.** Read the freeze script's rsync/copy line (e.g. `--exclude scratch --exclude dist ...`) and the go/no-go hygiene line (no scratch/, logs/, snapshots/, staging/, nested tree copies).
2. **Grep every pointer into an excluded folder**, outside node_modules and the excluded folders themselves:
   - config: `grep -rn 'scratch/\|logs/\|base"' *.json` (look for keys like hashIdentityBase, fixture roots, log dirs);
   - tools: grep each config key you found inside tools/ to see which tool READS it and what it writes when the path is missing (a try/catch that writes an empty result is the worst case: silent FAIL later);
   - docs and evidence: `grep -n 'scratch/' GAME.md evidence/*` (any claim or evidence line citing a path the auditor will not have).
3. **Check every audit-index Command for mutation.** For each Command cell: is it a read (node -e on a JSON, a header read, cat of a log) or a generator (npm run X, a session/smoke/fullsim/freeze script, gate-lite)? Open the generator's script: does it write into evidence/, screenshots/ or a scratch folder inside the tree? A generator in the index means the external sha256 manifest check fails once the auditor has run it. Extend the builder's own grep pattern: session|smoke|fullsim|npm run|freeze.
4. **Trace the failure mode to a verdict row.** For each pointer found, follow the code to the row it breaks (e.g. an identity check needs m > 0 and m equal to the count stated in the docs, while the missing base yields m = 0). Write file:line for the reader and the row. That makes it a measured-by-code-read defect, not a hunch.
5. **Turn each finding into a builder row with a two-sided proof:**
   - the dependency removed (e.g. record base hashes in config instead of reading a base tree), red quoted from running the tool on a copy WITHOUT the excluded folder, green after;
   - each generator Command replaced by a read of 60 s or less of its stored output, with 'Produced by <command>' moved into the Claim cell;
   - each doc/evidence citation re-measured into evidence/ or relabelled as measured on an earlier tree; generated files regenerated by their tool, never hand-edited.
6. **Require the rehearsal itself as the LAST builder row:** build the frozen copy the way the gate will (same excludes), state the file count with the find command, and write sha256 of every file OUTSIDE the copy. Then `shasum -c` = 0 non-OK. On the copy, run the test suite (count), the build, and every audit Command, timed, each 60 s or less. Then `shasum -c` again = 0 non-OK, which proves no Command mutated the copy.
7. **Merge, don't drip.** If a critique is running on the tree, hold these rows and send them in the one fix message after its verdict. Editing during a critique changes the tree under the critics.
8. **Check across siblings.** Grep the same config key across every live fork and kit folder; a kit-lineage defect is in every game. Put it in the next kit version and in each game's own gate prep.

## Mistakes to avoid
- Accepting 'freeze 13/13 PASS' from the build folder as proof for the frozen copy. It ran with scratch/ present.
- Trusting a builder's 'Command column grep = 0' without reading its pattern.
- Telling a builder to 'keep scratch/base' for hash identity and also requiring a frozen copy with no scratch/. Those two instructions conflict; resolve it in the spec.
- Copying old logs into evidence/ to dodge the path problem. The content belongs to an older tree and the mtime lies. Re-measure, or label the tree it came from.
