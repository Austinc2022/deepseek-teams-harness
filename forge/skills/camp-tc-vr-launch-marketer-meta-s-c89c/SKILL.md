description: Reviewing a compliance/questionnaire draft (age rating, data collection, privacy policy, GDPR/LGPD, children, localisation, status) before it is handed to the owner for a Meta Quest (or similar) store submission.
---

1. Cross-check every "does not apply / not in the plan" claim against the current market list in the build inventory (markets are often added late; juniors draft for the old plan). GDPR applies whenever EU users are in scope, LGPD whenever Brazil is — regardless of data collection.
2. Age ratings: never accept self-selected ratings (ESRB/PEGI/ClassInd). Ratings are assigned via the IARC questionnaire; the target audience ("10+") is not the content rating. Mild puzzle content expects ESRB E / PEGI 3 / ClassInd L — cite as expectation, not as the assigned rating.
3. Privacy policy URL: required on the listing even when zero data is collected. Absence = submission blocker, and the policy text needs lawyer review before it goes live.
4. Zero-data claims: keep the inventory precise (no accounts/cloud/analytics/SDKs/ads/IAP) and re-verify against the release candidate before submission. Two recurring build facts to check: does any local table capture player-entered name/initials (user data to disclose), and does the build contain outbound links.
5. Children: a 10+ audience includes under-13s (COPPA) and under-16s (GDPR-K). The compliance basis is deliberate zero collection — answers must say so per data category, not be waved off.
6. Localisation: store copy must be localised per region (DE → German, BR → Portuguese). If budget is unapproved, translations stay draft — never answer "no translation needed".
7. Mark each item KEEP / FIX / BLOCK, quote the offending text, give a corrected draft answer, and end with owner actions split into: owner must do, needs lawyer/native review, must remain draft. Verdict is RETURN WITH FIXES unless the draft is factually fabricated (then BLOCK). Never submit, publish, or contact authorities.
