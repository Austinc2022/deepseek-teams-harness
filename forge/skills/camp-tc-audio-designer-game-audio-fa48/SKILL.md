name: camp-tc-audio-designer-game-audio-fa48
description: When auditing a submitted game/VR audio spec against build-gate acceptance criteria (feedback sound coverage, spatial position/falloff, licence/synthesis source) before a PASS/FAIL verdict.
---

1. Enumerate the design's core actions from the brief (not from the spec), then enumerate every sound line in the spec. Build a two-column map: action -> sound. Any action without a triggered sound fails the feedback criterion; sounds for non-actions (music, ambience) don't count toward it.
2. Feedback criterion: for each action confirm the spec names a sound AND gives trigger condition, duration and a quantified mix level. Shared sounds across actions (e.g. one miss sound for two failure types) satisfy coverage but note the clarity cost as a non-blocking remark.
3. Spatial criterion: find every sound the spec marks as spatialised/3D/positional. Each must state (a) position — which transform, one source per object vs one pooled source — and (b) falloff model with numbers (inverse distance / linear / custom, ref distance, max distance). Vague phrases ("around the pads", "near the player") fail. Sounds that occur at world objects but whose spatial status is unstated (tap/impact sounds) also fail: the spec must either declare them 2D or give position+falloff.
4. Licence/synthesis criterion: per sound, demand one of: named library + licence + ID/author, or a concrete synthesis chain (oscillator/noise + filter + envelope). Watch for: bare sample mentions ("use a punchy click sample"), deferred sources ("sources to be chosen later"), licence contradictions (e.g. "CC0" plus "free for personal use" — CC0 is public domain, personal-use clauses are restrictive and block shipping), and content descriptions mistaken for synthesis ("60 Hz hum" without saying sine oscillator).
5. Verdict format: FAIL if any criterion fails; per criterion state PASS/FAIL, quote the exact offending lines verbatim in blockquotes, then give MINIMUM edits per line (replace one phrase, don't rewrite the spec). Flag non-blocking issues (typos, stray non-English text, unquantified levels like "should be quiet") separately and explicitly as not gate criteria.
6. Always state one concrete strength of the spec, and name which existing entry is the model the others should copy.
7. Common mistakes to avoid: failing a spec on style when it meets the letter of the criteria; counting an implied source ("60 Hz hum") as a stated synthesis method; treating the score bed as needing position if the spec declares it non-spatial; rewriting the whole spec instead of minimum phrase-level edits.
