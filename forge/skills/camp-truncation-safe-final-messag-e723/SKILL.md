# Truncation-safe final-message deliverable + coverage check

Graded text is the final message, and long messages lose their head. A brilliant section the grader cannot see scores zero. Follow this every time the deliverable lives in the final message.

## 1. Budget before writing
- Cap the whole message at ~6,000 words. Compress (tables, bullets, terse clauses) — never pad, never split the deliverable across messages.
- If the task's content genuinely cannot fit, cut depth (shorter rationale, tighter prose), never a required item.

## 2. Skeleton then fill
- Write the heading and one-line answer for every required section first, then fill. Every named section must be present in the message, with its required numbers on the page — never only cross-referenced ("see §4.4" without the number itself is a defect).

## 3. Citations at the point of claim
- Inline, complete URL + date checked, next to the claim it supports. Bare markers (S1, S3) and bare domains (meta.com) are not citations.
- Claims you could not verify: write UNVERIFIED in the body text where the claim appears.

## 4. End-of-message appendix (survives head truncation)
Close with two blocks, in this order:
1. **Sources** — full list: URL, date checked, what each supports.
2. **Required-items checklist** — every number, price, percentage, target and list the task named, restated as literals.
Place them LAST so they survive if the document head is cut.

## 5. Pre-send coverage check (do it literally, item by item)
- Walk the task's named items; confirm each appears as a literal string in the delivered text (fps/expansion %/prices per named region/disposition per named language/time targets…).
- Every named region, language, feature and input item gets an explicit disposition — including facts in input notes files not echoed in the brief (e.g. sample provenance that undermines a number).
- Every entry carries each metric dimension the task demands for it; if the task names N dimensions per demo, each demo shows N thresholds.

## 6. Thresholds and arithmetic
- Pass and fail values must partition the possible range: no grey zone. If a gap is deliberate, give an explicit retest rule for it.
- Give both sides of every threshold (pass trigger and fail trigger as hard numbers).
- Recompute every derived number (products, crossovers, percentages, totals) before sending.
- Check cross-references point at the right sections.

## Common mistakes
- Writing 10k words because the role allows it — the graded window is smaller than the role cap.
- Putting the bibliography at the top (it is the first thing lost).
- A required number present only in an earlier section or a referenced section.
- Reframing away a risk the task itself declared risky without on-page evidence.
