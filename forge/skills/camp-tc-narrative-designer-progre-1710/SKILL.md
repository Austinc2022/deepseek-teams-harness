description: Designing or reviewing progression, unlocks, difficulty or retention for a game when the only evidence is a short playtest summary with counts and coded complaints.
---

1. Extract every number and coded complaint from the brief; also mark what the brief says was NOT collected (e.g. "no story questions", "no reward variant tested") — those are hard no-go zones for claims.
2. For each proposed unlock, test the gate against cohort predictors, not sequential completion: cross-tab success vs player segments (e.g. 7/9 long-session vs 0/23 others). If finishing step N does not predict passing step N+1, the "gate on previous completion" chain is broken; redesign the gate around what actually predicted success.
3. Check gates against the target session length: if success requires session depth beyond the design target, add in-session teaching rather than lengthening sessions.
4. Difficulty curve: mechanical levers only (simultaneous faults, tool choices, time budgets, distractor symptoms). Never visual complexity. Place deliberate dips immediately after measured walls (where success collapses) and justify each dip with a count.
5. Return reasons: tie each to a specific quote/count. If the interview guide lacked a topic (story, rewards), say plainly the claim is unsupported and label any replacement a design bet, not a finding.
6. Retention hypotheses: baseline = measured return rate with raw fraction (e.g. 53% = 17/32), state direction and size, define "returned" and the window exactly, give a falsifier plus one guardrail (e.g. session bloat). Never measure retention with session length or ratings unless those were collected as return measures.
7. When reviewing a junior draft, list the three most damaging unsupported claims each with the exact figure that refutes it.
